# ADR-001: 大分類Gの情報DBと低コスト連絡先補完

**Status:** Accepted

**Date:** 2026-08-24
**Deciders:** プロジェクト所有者

## Context

日本標準産業分類の大分類`G`は、情報通信業の中分類37〜41とその全小分類・細分類である。したがって既存の`G37-41`は範囲としてはG全体だが、表示・設計上の正本は`G`とする。既存ファイル名は配布互換のため維持する。

2026-08-24の旧スナップショットは59,582社で、HP 4,380社、電話188社、法人番号20,239社だった。欠損をLLMで全件検索すると高価で、誤同定も起こる。

## Decision

1. FUMA行をGの母集団とし、全国法人マスタと統合する。
2. 法人番号の回復は、法人格を保持した正規化社名と、漢数字・丁目・番地表記を正規化した本店住所が双方で一意に完全一致した場合だけ採用する。
3. HP・電話は正規マスタへ無根拠に上書きせず、候補、出典URL、取得日時、信頼度、レビュー状態を保持する。
4. 処理順は「ローカル公的データ照合→既知公式HPのHTML/JSON-LD/tel抽出→予算上限付きHP候補検索→低信頼候補のみLLM判定」とする。
5. LLMがURLや電話番号を創作したり、根拠URLなしで確定値にしたりすることを禁止する。

## Cost policy

既存アプリのLLMは`gpt-5.6-luna`を使う。APIで使う場合の2026-08-24時点の公式価格は入力$0.20/100万token、出力$1.20/100万tokenである。Web searchツールは全モデル$10/1,000回に加え、検索内容token料が必要である。

そのため、55,201社のHP欠損を1社1検索で全件実行すると、ツール呼出しだけで約$552.01とtoken料がかかる。これは行わない。既定値は次の通りとする。

- `max_search_calls_per_run = 1,000`
- `max_llm_reviews_per_run = 200`
- 検索優先度: 法人番号あり、HPなし、営業・調査対象リストに含まれる企業から
- 予算は実行前上限と実績を表示し、APIキーはDB・ログ・リポジトリに保存しない

参考: [OpenAI Models](https://developers.openai.com/api/docs/models), [OpenAI API Pricing](https://openai.com/api/pricing/)

## Verified result

2026-08-24の実データ再生成結果:

| 指標 | 旧版 | 新版 |
| --- | ---: | ---: |
| 統合企業 | 59,582 | 59,581 |
| 法人番号あり | 20,239 | 52,490 |
| FUMA-only | 39,343 | 7,091 |
| HPあり | 4,380 | 4,380 |
| 電話あり | 188 | 188 |
| 法人番号重複 | 0 | 0 |

回復候補32,258社のうち、既存の明示法人番号との衝突2件、その他の曖昧・重複6件を除外し、32,252社を採用した。総数1社の減少は、FUMA行と既存の全国G行が同一法人として統合された結果である。

## Consequences

- 法人番号を使ったHP候補の同定・証拠確認を52,490社で実施できる。
- HP自体の回復はまだ進んでいない。法人番号は検索・検証キーであり、HP存在の保証ではない。
- FUMA-only 7,091社は無理に一致させず保持する。
- フル生成はJSONL COPYで約123秒。中断WALは次回生成前に除去する。
